# IronWill · Windows 0.1.6 / Android 0.1.2  ---------"This tool launches psychological assaults on the user to break procrastination, distraction, and evasive behaviors."
本工具尝试精神攻击用户，解决用户的拖延，分心，逃避等低效行为。


这是可运行的个人测试版：Windows 负责三档监督与可选灰区 AI；Android 负责应用级轻提醒、通知和局域网联动。目标、现实处境、拖延后果与誓言由你填写，程序引用原话。执行周期由你开始、暂停、继续和结束，没有固定每日起止时间。

## 快速开始

本机运行桌面端（已验证Python 3.14.7；Windows PowerShell）：

```powershell
cd desktop
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

## 先用 Windows

1. 双击 EXE，无需安装 Python。打开界面本身不会开始监督。
2. 在“当前周期”填写主线，以及希望提醒出现的现实处境、后果、誓言。保存自己的设置。
3. 到规则页填入红线进程或标题关键词，并填写常用主线进程/标题。例如把确实用于娱乐的应用列为红线，把当前工作的工具列为主线。规则必须依据自己的活动选择；浏览器整体列为主线，会使其中的红线标题也被进程白名单放行。
4. 可先预览提醒。预览不计时、不升档、不锁屏。
5. 点击开始，使用右上角“最小化到托盘”后继续自己的工作。点击右下角 IronWill 图标恢复窗口，右键可打开或停止并退出；图标可能被 Windows 收在通知区域的展开菜单中。收起不暂停监督，普通最小化也可继续运行。关闭主窗口仍会确认退出，本版没有开机自启。

默认首次红线累计 30 秒提醒，之后每累计 15 分钟红线升一档，最多三档。这个时间只计入当前周期中有效、非空闲的采样。连续回到主线 60 秒才清除档位，点击“返回”本身不等于已经完成回归。第一、二档的“值得”“喘息”各提供 15 分钟有效活动时间的暂缓；第三档不再提供这两个选择。

第三档可请求单次 Windows 锁屏，但要先启用锁屏选项，再亲自选择。第一版没有自动复锁、监督期或自删除。模型判定只能产生灰区建议，不能独自推进三档或锁屏。没有规则且不开 AI 时，不会凭空判断你在摸鱼。

“当前周期”的“当前判断”显示当前窗口由什么规则处理、AI 是否完成审核、判断理由、缓存来源、暂缓/提醒冷却，以及未输入造成的空闲。**没有提醒不等于 AI 已判断你很专注**；未启用、白名单跳过、网络失败、信息不足分别显示。隐私窗口不展示标题。

## 判断日志与 AI 通信（Windows 0.1.3）

新增“判断日志”页面，按时间查看本地判断、命中规则、AI 结论、提醒及周期操作。相同窗口和结论不逐秒重复写入，变化时记录，持续不变约每分钟补一条。可按“判断 / AI通信 / 程序”筛选、搜索、导出筛选结果或清空日志；取消“跟随最新”可停留查看已有条目。

点击 AI 通信条目可看请求 ID、服务地址、模型、请求 JSON、服务返回正文、HTTP 状态与耗时。缓存命中明确标为“本次没有发送 HTTP 请求”；失败、信息不足、过期结果分开呈现。日志不发送到手机或模型，也不改变原有升档规则。HTTP 错误正文不保存，只记录安全的错误类别；成功响应正文超过 12000 字符会截断，页面明确标记。

日志保存在默认数据目录的`logs/activity.jsonl`和`logs/activity.previous.jsonl`，每份最多约 2 MiB，轮换覆盖旧记录，页面最多载入最近 1000 条。重开程序可查看留存记录；日志是本地明文，可能包含目标、非隐私标题和模型正文。隐私命中不写窗口进程和标题，Key、Authorization 头不记录，已知密钥会屏蔽。清空只删除这两份日志，不删除目标、规则或 Key；已有导出文件由你自行管理。它是有界诊断日志，不是永久完整审计档案。

默认界面需要约 820 × 650 的可用窗口空间，本次在 Windows 11 64 位构建。EXE 未做商业代码签名，系统可能显示未知发布者；可以先核对 Releases 同版本的 SHA-256 或从源码自行构建。

## 再用 Android

1. 把 APK 传到自己的手机，使用系统安装器安装。它是自行安装的开发签名版本，不是应用商店版本。
2. 填写承诺和当前主线，选择至少一个红线应用。
3. 在应用内打开通知权限与提醒测试，允许通知；再开启“使用情况访问”。可选无障碍只读取前台应用包名，不读取页面内容。
4. 回到 IronWill，点击“开始 / 继续这一轮”。切到红线应用持续约一分钟会触发轻提醒。

手机首版是应用级提醒：可以识别你选择的娱乐应用，但不能区分同一个浏览器里“查资料”与“刷网页”。通知的“返回主线”暂缓两分钟，“值得”“喘息”暂缓十五分钟。手机目前没有桌面端完整的三档状态机。

系统停止后台服务后需要打开应用并继续。首次安装、手机重启都不会自动开始监测。手表如果已配置手机通知镜像，可能收到同一通知；没有独立手表应用或送达保证。详细权限与故障说明见 [Android 安装说明](android/README.md)。

## 可选：让两端互通

两端可以各自离线运行。联动需要手机与电脑在能够互通的网络中。

1. Windows 的手机与 AI 页中启用局域网服务。
2. 将界面显示的 HTTPS 地址、证书指纹和配对令牌填入手机；核对后验证并保存。不要把这些配对资料公开发送给别人。
3. 手机可先查看电脑状态，再手动导入电脑的目标和誓言。导入前有确认，导入不会自动开始周期。
4. 手机也可向电脑提交当前周期的返回、值得、喘息、暂停或继续。锁屏不能通过联动远程触发。

联动只共享目标、誓言和有限状态，不共享现实处境、后果、窗口标题、AI 密钥。电脑默认使用 8765 端口；若防火墙阻止连接，需按自己的网络情况允许该程序在私人网络通信，本项目不会自动修改防火墙。不要做公网端口映射。

30 秒提醒去重只减少两台设备同时响起，不是全局惩罚计数同步。断网时两端各自工作，可能分别提醒。退出电脑程序或关闭局域网服务后，手机仍能进行自己的本地提醒。

## 可选 AI

### 单字符分类（0.1.6）

模型只回复`1`（核心相关）、`2`（辅助/中立或信息不足）或`0`（明确无关），显示说明由程序生成。`2`保持安静，也不清除已有档位；`0`仍只作语义提醒。请求使用`max_tokens=1`、`temperature=0`，移除JSON输出模式。DeepSeek官方地址自动加入`thinking: {"type":"disabled"}`，可填写`https://api.deepseek.com`与`deepseek-flash`，依据[官方API](https://api-docs.deepseek.com/api/create-chat-completion/)。其他兼容服务需支持单token非思考输出，不会收到DeepSeek专属参数。

日志显示实际数字、固定分类说明、finish_reason及服务提供的输入/输出token用量。空回复、多字符、旧JSON、思考或中断回复均按审核失败处理，不自动扩大预算或追加请求。一个生成token不等于只付费一个token，也不保证几毫秒完成；输入与网络耗时仍存在。本轮用合成响应验证，未实连付费模型测延迟或准确率。

### 减少重复审核（0.1.3）

“手机与AI”页新增“已审核窗口复用期限”，默认**本工作周期**，也可选择15/30/60分钟，点击应用AI设置后生效。同一目标下已审核的进程＋页面标题再次出现，直接复用结论，不启动网络请求；进程和关键词本地规则已有结论时仍优先跳过AI。标题只规范空白和大小写，保留数字、项目名和页面内容差异，不把某个网页的结论推广到整个浏览器。

判断记忆最多512条，保存在`ai_judgments.json`，重开后继续同一个暂停周期可复用；新周期、目标、规则、服务地址、模型或提示版本变化不会沿用旧结论。结束周期按钮或“清空判断缓存”可清除记忆。缓存文件只保存身份摘要、周期、时间和结论/理由，不保存Key或窗口原文，但理由可能复述个人内容，仍是本地明文。

新标题需稳定停留至少3秒才申请审核，自动请求至少间隔30秒，失败退避从30秒逐步增加到最多5分钟。0.1.6的三个有效类别使用所选复用期限；旧unknown格式最多5分钟，网络失败不当作已完成判断。新协议版本自动隔离旧JSON结论，无需手动清理原配置。手动虚拟连接测试是显式请求，绕过这些缓存与自动限频。页面分别显示实际API请求数与窗口缓存复用次数；刷新页面、每秒采样和缓存访问都不增加API次数。清空日志不清空判断缓存，两者按钮分开。

Windows 可填写兼容的聊天补全接口地址、模型名和密钥后启用。默认不开启。它只处理本地规则无法判断的灰区，发送当前主线、进程名、窗口标题，不发送你的处境、后果、誓言或完整历史。隐私词优先拦截；远程服务必须是 HTTPS，本机服务允许回环 HTTP。

标题本身可能包含敏感内容，启用前应了解自己选择的服务。0.1.2新增“在本机记住API Key”：勾选后应用设置，用Windows账户加密保存；下次Key输入框留空即可复用。未勾选时仅用于本次运行。保存内容绑定服务地址，改成另一个服务时不会把原服务Key发过去。密钥不写入普通JSON设置，也不进入源码包。第一版没有用真实付费模型做端到端验收。无密钥、超时、格式错误或过期回复都不能据此算作偏离。

也支持`IRONWILL_API_KEY`；旧版`DEEPSEEK_API_KEY`仅在官方`https://api.deepseek.com`服务上复用。可以点击“从旧版DeepSeek文件导入”选择原来的`deepseek_key.txt`，导入先填入掩码框，应用设置后才保存和启用；旧文件不会被改动。地址/模型为空时按核查的[DeepSeek官方接口说明](https://api-docs.deepseek.com/)填入`https://api.deepseek.com`与`deepseek-flash`，已有配置不自动替换。

“删除已保存Key”移除本机加密副本并关闭AI，不撤销服务商账户中的Key。取消“记住”后应用设置，也会移除本机副本，当前运行仍可用；未保存的Key在退出后无法从这个程序恢复。若从未留存旧Key，仍需要在原服务商处重建一次，随后勾选记住，避免反复申请。请直接在程序里输入Key。

本版只保存最近一次配置的一份服务Key；换服务并记住新Key会替换旧副本。临时Key也绑定当前服务，关闭再启用AI仍可在同一次运行中复用，退出程序后才需要重新提供。

**红线标题可以留空**。填写模型配置、勾选启用并应用后，未被隐私、进程或标题规则提前处理的窗口会交给 AI。判断相关则保持安静，判断可能偏离则弹出语义提醒。主线进程白名单优先于 AI，因此不要把需要逐页审核的整个浏览器放进主线进程列表。

可以先点击“用虚拟数据测试 AI 连接”。它发出一次虚拟请求、跳过缓存，不发送自己的任务或真实窗口，也不改变周期和档位。认证失败、限流、接口错误、网络错误、超时或格式不兼容会显示具体类别。测试通过只证明协议可用，不代表 AI 已审核你的当前活动；开始周期后再看“当前判断”。每次重新打开程序都需重新启用 AI。

## 个人数据保存在哪里

- Windows：`%LOCALAPPDATA%\IronWill` 下的 `ui_settings.json`、`policy.json`、`session.json`、`ai_judgments.json`及`logs`中的判断/通信日志；启用配对后另有 `pairing` 证书、私钥、令牌。以上仍是普通本地文件；选择记住的AI Key单独保存在`secrets/ai-key.dpapi`，由Windows账户保护。整个数据目录不是加密保险库，不要放进公共同步目录。
- Android：应用私有存储，保存输入、规则、周期、配对资料及最近 200 条记录。Manifest 和备份规则关闭自动备份；卸载或清除应用数据会移除本地内容。
- 两端没有云端账户、上传历史、排行榜或自动成果评价。数据恢复、加密备份与批量迁移未实现。

退出程序后可以自行备份或清理数据。Windows 删除 EXE 不会同时删除个人数据；停止配对后，已有配对令牌仍留在电脑，若需要彻底撤销旧手机，关闭程序后移走整个 `pairing` 目录，下次开启服务会生成新资料，需要重新配对。

## 从源码运行与构建

Windows 源码位于 `desktop/`。已验证 Python 3.14.7；建议独立虚拟环境。

```powershell
cd desktop
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -m ironwill --demo
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\build.ps1 -Python .\.venv\Scripts\python.exe
```

普通启动使用 `python -m ironwill`，不会自动开始。`python -m ironwill run` 明确请求用已保存目标开始；无目标时仍需填写。`--help` 不加载监测，不读取旧配置。仅桌面本地规则运行时可不安装配对依赖，但完整打包需要 requirements 中的库。

Android 可用 Android SDK 与 JDK 直接构建，无需下载 Gradle 依赖。命令、签名说明与 SDK 要求见 [android/README.md](android/README.md)。源码包不包含开发签名私钥；本机现有私钥在 `android/build/ironwill-development.jks`，希望以后覆盖升级当前 APK 时应妥善保留。

Windows 0.1.6完整149项测试和EXE隐藏自检通过，包含日志、缓存、托盘、凭据、许可资源和局域网连接上限；Android 0.1.2重新构建、GPL资源、开发签名及26项JVM断言通过。详细范围见[验证记录](docs/verification.md)。Android真机安装、厂商后台限制、实际通知及锁屏仍待验收。

升级cryptography wheel时，在已安装该wheel的构建环境中，从仓库根目录执行`python tools/collect_dependency_licenses.py`重新收集SBOM对应crate许可；它只下载公开归档并核验哈希，不执行第三方源码或安装新运行库。公开发布前运行`python tools/audit_publication.py --history`并核对[开源审查](docs/open_source_review.md)。
