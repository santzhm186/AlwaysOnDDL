# IronWill 首版桌面使用与 UI 实现说明

## 首次使用

1. 打开 IronWill，先在“当前周期”填写当前主线，以及愿意保存的现实、后果和大愿原文。署名可以留空。现实、后果和大愿保留输入原文，不由模型改写。
2. 在“判定规则”添加自己的红线与主线关键词。每行一项；进程规则填写应用进程名，标题规则填写明确的标题关键词。通用浏览器可能同时用于工作和娱乐，不建议把整个浏览器进程归入某一类。
3. 点击“保存并应用规则”。没有红线且未启用 AI 时，程序会明确提示不能自动判断分心，不会把空规则包装成有效监督。
4. 点击“开始周期”才开始本机窗口采样。暂停期间停止采样和累计；继续重新建立基线。结束只结束当前周期，不判断成果，不删除文件。
5. “体验提醒”使用安全的模拟文案。体验第三档的任何选择都不会升档、锁屏或写入惩罚记录；有真实提醒正在显示时，先处理或关闭真实提醒。

程序没有固定每日开始/结束时刻，没有成果仪表盘，也没有防退出或防破解功能。关闭主窗口会询问是否停止并退出；确认后停止本机监督和配对服务。

## 提醒、选择和锁屏

- 本地红线触发分档提醒；默认首次累计 30 秒，此后每额外累计 900 秒升级。暂停、锁定、检测不可用、空闲或采样断档不会被直接补算成偏离。
- 第一档引用当前周期的现实原文，第二档引用后果原文，第三档引用大愿原文。提醒窗口是非模态窗口；它不会阻塞采样，也不会抢占系统退出能力。
- 前两档直接提供“返回主线”“这值得”“喘息一下”。“这值得”无需强制填写申辩文字。
- 第三档提供返回和显式锁屏。锁屏权限默认关闭；必须先启用并保存该权限，再在真实第三档中亲自点击“锁屏”，才调用 Windows 锁屏。不会自动锁屏。
- 点击返回只表达返回意图；连续相关活动达到恢复阈值后才清档，按钮本身不宣告已经工作或已经产生成果。
- AI 灰区建议使用独立的“语义提醒 · 不计档位”窗口，不增加档位，没有锁屏按钮；关闭它不会更改真实执行档位。
- 自毁保险保留，本版没有删除软件或卸载的实现。不会通过日常提醒走进删除流程。

## 手机配对

“手机与 AI”页面中的“启动手机配对”是独立的显式操作；打开软件不会自动开放端口。

启动后，将连接地址、设备口令和证书指纹填入手机端。设备口令默认隐藏，只有点击显示或复制时才提供。请仅在信任的局域网配对。桌面配对服务使用 HTTPS；手机需核对固定证书指纹，不应跳过证书验证。

桌面向手机共享当前周期的目标、大愿、状态、周期 ID 和档位；不共享现实、后果、窗口标题、AI 密钥。手机显示的是设备各自的监督状态，不是跨设备统一的成果判定或处罚状态。

两端在短时间内协调提醒展示。若桌面提醒被另一端的最近提醒暂时抑制，桌面保留待展示提醒并延后重试；第三档不会因此永久丢失。暂停、结束、实际恢复或有效选择会取消相应待展示提醒。

手机发出的选择必须带当前桌面周期 ID，且桌面存在真实提醒窗口；暂停/继续需匹配当前状态。过期周期、无有效提醒或体验/语义提醒上的远程选择不会冒充有效执行动作。

## 可选 AI

AI 默认关闭。填写兼容服务的地址和模型名，选择本次运行启用，再点击“应用 AI 设置”。服务地址可为完整聊天接口或兼容的 `/v1` 基址；客户端会补全聊天接口路径。远程服务要求 HTTPS，本机服务可以使用 HTTP。

只有本地规则判为灰区的窗口才会请求 AI；隐私规则命中、设备锁定、空闲、检测失败时不会发出相关请求。发送内容限当前目标、进程名和必要标题。现实、后果、大愿和署名不发给模型。

API密钥默认只用于当前运行；0.1.2允许勾选“在本机记住API Key”，应用后使用Windows账户加密保存，下一次输入框留空即可读取。也可读取`IRONWILL_API_KEY`；旧`DEEPSEEK_API_KEY`只匹配官方DeepSeek服务。普通设置文件只保存服务地址和模型名。服务地址禁止嵌入用户名、密码、查询参数或片段，以免把凭据保存进地址字段。取消“启用AI”会立即停止使用AI；已发出的请求无法撤回，旧结果不再应用。

从旧版文件导入只读取用户选择的单行Key，内容不回显到状态文本；导入不联网、不自动开始，旧文件保持原样。已有本次运行Key也可勾选记住后直接再应用，无需重新输入。取消“记住”后应用会删除磁盘副本并保留本次运行可用；“删除已保存Key”则同时关闭AI并清理当前输入。读写或解密失败不降级成明文保存。

请求在后台线程执行，结果由主 UI 线程领取；周期、规则或 AI 设置变化后的旧结果会被丢弃。模型判断相关可帮助识别返回主线；判断无关只给建议，不替代本地规则升档。请求失败或拿不准时放行。

## 为什么没有提醒（0.1.1）

“当前周期”底部新增“当前判断”。先确认它显示监督中，再观察当前窗口是否被实际采样。没有红线标题也可以使用AI：未匹配窗口会进入灰区；AI认为不相关时出现语义提醒，认为相关时保持安静。整个浏览器若列为主线进程会跳过AI，应按需要移除该规则。

面板分别解释：AI未启用、主线白名单、隐私命中、输入空闲、采样不可用、审核中、模型认为信息不足和接口失败。当前审核理由只应用于同一周期/配置/窗口的新鲜结果。显示最近结果是否来自缓存及本次运行收到的有效审核次数；不保存标题历史。输入空闲只表示系统未收到输入，阅读与思考也可能达到阈值。

手机与AI页中的“用虚拟数据测试AI连接”需要先应用AI配置。测试用固定虚拟数据、跳过缓存，不读取真实窗口，也不改变周期/档位。可用结果与服务失败明确区分；密钥认证、权限、接口地址、限流、超时或响应格式问题只显示安全的类别和处理方向。退出再打开后仍需重新启用AI。

## 本地文件

默认目录为 `%LOCALAPPDATA%/IronWill`。可以用 `--data-dir` 指定其他目录。

| 文件 | 内容 |
|---|---|
| `ui_settings.json` | 当前编辑内容、署名、AI 地址与模型名；不含 API 密钥 |
| `policy.json` | 本地规则列表、计时参数、显式锁屏权限 |
| `session.json` | 当前周期快照，包含用户原文和状态；不包含采集到的窗口标题历史 |
| `secrets/ai-key.dpapi` | 用户选择记住的AI Key及服务绑定信息，Windows账户加密；不会回填到输入框 |

除明确的DPAPI密钥文件外，设置和周期仍是普通本地文件。它们使用唯一临时文件和原子替换；Key先加密再写临时文件。当前UI不读取或改写那四个旧版源文件，也不会把旧实例配置当发行模板自动导入。升级继续使用同一数据目录；DPAPI副本通常只适合原Windows账户使用，不能当作跨账号的明文Key备份。

重新打开时，未完成周期恢复成暂停；不会自动采样或补算离线时长。若用户主动使用 `run` 命令，则按这一明确指令开始或继续保存的周期。

## 开发与验证入口

在 `desktop` 目录运行：

```text
python -m ironwill --help
python -m ironwill
python -m ironwill --demo
python -m ironwill run
python -m ironwill --data-dir PATH
python -m ironwill --self-check RESULT.json
python tests/run_ui_checks.py
```

- `--help` 在导入图形应用前解析和退出，不启动窗口采样、网络或锁屏。
- 默认打开界面但不开始监督；`run` 是命令行显式开始入口，首次未填目标时仍需先填写目标。
- `--demo` 只使用内存中的示例，不读取个人配置、不采样、不联网、不锁屏、不保存个人状态。
- `--self-check` 是隐藏开发参数：构造隐藏的安全体验界面，验证体验操作前后状态一致，将结果写到指定 JSON 路径并退出。可用于验证打包后的窗口应用是否包含 Tk 和必需模块。
- `tests/run_ui_checks.py` 执行隐藏 UI 边界测试。Windows 采样、锁屏及错误弹窗均替换为测试实现；测试不连接外部服务，不操作真实锁屏。无 Tk 桌面环境时明确跳过，不能把跳过宣称为图形验证通过。

0.1.1覆盖22项UI边界：原有15项包括未开始不采样、默认参数、原文保存、空规则提示、体验隔离、锁屏权限与显式选择、直接“这值得”、语义提醒、手机周期隔离、第三档重试、回主线关闭旧提醒、暂停停止采样、密钥不落盘、地址凭据拦截及AI设置不自动请求。0.1.1新增无红线标题仍可由AI提醒、白名单/未启用解释、隐私标题隐藏/空闲解释、审核失败与模型信息不足区分、旧窗口/旧设置诊断隔离、虚拟连接测试状态隔离及旧连接测试回调失效。

主要源文件：`ironwill/app.py` 负责 Tk 界面、UI 线程调度和接口适配；`ironwill/__main__.py` 负责显式命令入口；`ironwill/__init__.py` 不执行监控副作用。核心规则、Windows 系统调用、模型访问和 HTTPS 中继分别留在独立模块。

0.1.2增加10项UI边界测试，UI总计32项：重开复用、保存/临时Key服务地址隔离、本次Key转保存、关闭再启用保留临时Key、删除与关闭、取消记住、保存失败无明文回退、旧文件只读导入与防止导入到错误服务。另有11项凭据输入与实际DPAPI测试。完整桌面回归94项通过。
