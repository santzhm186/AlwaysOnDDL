# IronWill · 发布范围与后续工作

## Windows 0.1.2（2026-10-10）

在原程序和原数据目录上改进Key复用：可选Windows账户加密保存，重开后留空自动读取；支持删除本机副本、本次运行Key转为保存、旧版`deepseek_key.txt`只读导入，以及对官方服务受限的`DEEPSEEK_API_KEY`兼容。改变服务地址不会复用原服务保存的Key，保存失败不回退明文。目标、规则和快照格式兼容；新增固定`IronWill.exe`入口，版本归档仍保留。没有找回从未留存的旧Key的能力。

新增21项凭据/UI测试，完整94项通过；EXE自检增加真实DPAPI合成Key往返，不访问真实Key或模型服务。临时Key也绑定服务，并支持同一次运行关闭再启用AI时复用。Android本轮未改。

## Windows 0.1.1（2026-10-10）

根据首次试用反馈，补上“没有提醒”的可观察原因。无需填写红线标题，已启用AI会审核未匹配窗口；判断可能偏离时触发已有语义提醒。当前周期页显示规则来源、当前窗口、AI判断理由、缓存来源和有效审核次数，隐私标题隐藏。AI未启用、白名单跳过、输入空闲与接口故障均明确说明。

增加用虚拟数据手动测试AI连接的按钮，区分真实模型信息不足与认证/网络/协议失败。测试不发送用户任务/真实窗口，不改变档位；错误不包含服务原始正文或凭据。新增10项针对性测试，全套73项通过。新EXE与旧版并存，数据目录和格式兼容；Android仍为0.1。

## 设计保留与实际取舍

你的判断仍是产品的前提：由你写下现实压力、目标、后果、誓言，程序将这些内容放到你面前。没有固定每日起止，没有对成果打分，没有防卸载竞赛，也没有把身体信号用作是否认真工作的证据。

“未知”是程序观察失败的技术状态，不是给用户添加的第四个回答选项。窗口拿不到、手机被系统暂停、AI 格式错误时没有证据，程序就不编造一次违约。明确的红线规则与用户自己的决定才驱动规则行为。

Windows 已实现三档提醒、连续回归、暂缓、可选单次锁屏及灰区语义建议。Android 当前实现包级轻提醒，未追平 Windows 的三档机制。两端有可选 HTTPS 配对、有限状态与手动任务导入、电脑选择提交和提醒去重；没有统一全局惩罚账本。

原型中的自动复锁、逐字忏悔、终局自删除不在这次实现中。这是首版交付范围，不代表已经把完整产品机制永久改成另一套；原始文件没有改写。那些机制需要独立、可恢复的动作状态与真实设备验收，不能把删除源码目录当作卸载实现。

## 已知限制

| 项目 | 当前影响 | 后续处理 |
|---|---|---|
| Android 真机未连接 | 无法证明安装后的界面、权限、通知、后台存活与锁屏行为 | 先在一台实际使用的手机完成验收清单，再扩展 ROM 范围 |
| Windows 只验证本机环境 | 未覆盖 Win10、不同缩放比例、RDP/多会话、长期睡眠恢复 | 建立平台验收矩阵；当前支持声明限于已测环境 |
| 两端感知不同 | Windows 有标题；手机只有应用包名，浏览器内用途无法区分 | 如需要，后续增加用户声明或选择性语义输入，不假装已有可见内容 |
| 手机仅轻提醒 | 两端暂缓与升级规则不同 | 抽取共享协议测试向量，按明确规范追平状态机 |
| 手机后台由系统管理 | 服务可能被终止或延迟，通知可被用户关闭 | 展示真实监测状态，真机测厂商限制；不声称保证常驻 |
| Windows 无托盘/自启 | 关闭主窗口即停止，最小化可继续 | 后续增加明确的托盘行为和用户选择的自启 |
| 无单实例互斥 | 多开桌面程序可能争用同一数据文件和配对端口 | 本版请只运行一个实例；后续加入按数据目录互斥 |
| 本地明文设置 | 同一账户可读取自己的处境、誓言与配对资料 | 后续使用系统凭据库保护 token，另设计导出和加密备份 |
| 事件记录未统一 | 手机保留最近200条，桌面只保留当前快照与设置 | 后续补可导出的本地事件账本；不先增加云服务 |
| 有限联动 | 30秒去重不是统一状态，断网可能双端重复提醒 | 如确有需求，再实现幂等事件 outbox、设备撤销和冲突规则 |
| Android 目标 API 35 | 当前侧载可用性与商店发布是不同验收范围 | 商店发布前调整目标 API、签名和敏感权限用途说明 |
| 模型未实连 | 自动测试使用模拟服务，不能证明某服务兼容 | 由用户选择服务后做一轮最小数据的连接测试 |

## 实际效果怎么判断

本版能减少“承诺被忘掉”的机会，也能在明确红线活动持续时把提醒送到面前。但没有证据说明更尖锐的话一定带来更多行动；也不能按 INTP 标签预言个人效果。效果还取决于规则是否准确、当下任务是否可执行，以及提醒是否已经变成背景噪音。

建议第一轮个人试用只观察一项主线，先用默认强度。每天自行记下：收到几次有效提醒、几次误提醒、收到提醒后是否真正返回，以及是否开始为了躲通知而改设置。这个观察不要求程序验收成果。若提醒增加但行动不增加，应先检查规则与出现时机，而不是自动加大措辞或锁屏次数。

具体措辞可以保留冷峻感，但程序只能引用你确认过的现实与后果。它没有证据替你生成关于人格、能力或未来结局的新判断；这也是第一版固定模板、AI 不生成惩罚话术的实现边界。

## 后续顺序

1. 真机验收：安装、权限拒绝/撤回、红线提醒、旧通知失效、旋转和进程恢复、断网、锁屏与 Wear 镜像。
2. 桌面体验：托盘、单实例、DPI、可读的故障诊断和显式导出。
3. 状态一致性：统一两端周期/选择含义，补本地事件账本与跨端幂等回执；保留离线独立运行。
4. 需要时再扩展强约束、分发与云服务，每一项单独定义失败恢复和验收标准。
