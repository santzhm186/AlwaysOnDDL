## Windows 0.1.7（2026-10-13）

周期页将当前主线拆为长期目标与短期Todo，旧goal原样作为长期目标。短期待办支持每行一项批量添加、编辑、移除、勾选与取消，稳定ID允许同名任务分别记录；持久化最多100项，每项500字符。添加/勾选即时保存，失败回滚，不自动保存其他未提交的编辑，也不自动清理已完成记录或结束周期。

AI优先且仅参考未完成待办；全部完成或列表为空后才参考已保存长期目标。参考变化立即丢弃旧结果、重置采样/连续恢复基线并隔离缓存，原档位、偏离时间和周期ID保持。长清单公平分配4000字符预算，无可用目标时不发AI请求。添加goals/checklist模块与25项数据、迁移、保存失败、AI发送边界及悬浮联动测试，完整177项通过；Android仍为0.1.2，本轮未修改。

## Windows 0.1.6（2026-10-12）

AI相关性审核从JSON及模型理由改为单字符0/1/2，max_tokens=1、temperature=0。DeepSeek官方HTTPS地址自动关闭思考，其他服务不附加专属参数。固定system规则和最小JSON用户数据保留任务/标题指令边界，按任务目的判断，不把教程视频等一律判成娱乐；无新增SDK或依赖。

增加neutral类别：辅助/中立或信息不足保持安静，不清已有档位。说明由本机固定映射，实际数字与原始回复可查；日志补充protocol、finish_reason和服务提供的有效usage计数。只接受去除首尾空白后的ASCII 0/1/2，允许完整数字以length结束；空/额外文字、旧JSON、思考、工具调用、过滤和中断失败开放，不自动扩大token预算、改模型或隐藏重试。协议修订隔离旧缓存，原期限、限频和退避保持；有效neutral可跨同周期重开复用。

新增12项有意义的协议、缓存、UI与核心回归，完整149项通过。未使用真实Key或付费模型验证延迟/准确率，不承诺1token即几毫秒或只有1token账单。Android不直接调用AI，本轮代码和0.1.2安装包不变。

## Windows 0.1.3（2026-10-11）

新增第四页“判断日志”，持久化本地规则判断、AI结果和周期/提醒事件，可筛选、搜索、查看详情、导出和清空。AI实际请求与响应带相同request_id，显示JSON正文、HTTP状态和耗时，缓存、失败、信息不足、过期未采用分别标明。日志最多两份各2MiB、页面最近1000条；不记录隐私窗口标题/进程和Authorization头，已知Key屏蔽。正常模型回复正文有界记录，HTTP错误正文不保留。日志故障不会改变监督策略。

新增右上角“最小化到托盘”，后台周期保持原状态，点击图标恢复、右键打开/退出，图标添加失败保持窗口可见。使用Windows自带DLL与Python标准库，无新第三方运行依赖。目标、规则、Key和周期沿用原数据目录，Android本轮不变。构建和实际测试范围见verification.md。

补充工作周期判断记忆，默认同周期复用已审核进程/标题，可选15/30/60分钟；最多512条，跨同周期异常重开可复用。窗口稳定3秒才审，自动请求至少间隔30秒，失败退避至5分钟。API实际请求与复用分别计数，缓存失效或手动清空可重新审核。目标/规则/服务/模型/提示变化隔离旧结果；已有本地进程/关键词规则继续优先，页面判断不扩大成全进程规则。

新增41项测试，完整135项通过；四页打包EXE隐藏自检通过，实际原生托盘创建/恢复消息/清理通过。固定入口若仍被旧版占用，构建保留旧实例，交付独立`IronWill-Windows-0.1.3.exe`，不会强制关闭用户正在运行的监督。

## 设计保留与实际取舍

你的判断仍是产品的前提：由你写下现实压力、目标、后果、誓言，程序将这些内容放到你面前。没有固定每日起止，没有对成果打分，没有防卸载竞赛，也没有把身体信号用作是否认真工作的证据。

“未知”是程序观察失败的技术状态，不是给用户添加的第四个回答选项。窗口拿不到、手机被系统暂停、AI 格式错误时没有证据，程序就不编造一次违约。明确的红线规则与用户自己的决定才驱动规则行为。

Windows 已实现三档提醒、连续回归、暂缓、可选单次锁屏及灰区语义建议。Android 当前实现包级轻提醒，未追平 Windows 的三档机制。两端有可选 HTTPS 配对、有限状态与手动任务导入、电脑选择提交和提醒去重；没有统一全局惩罚账本。

原型中的自动复锁、逐字忏悔、终局自删除不在这次实现中。这是首版交付范围，不代表已经把完整产品机制永久改成另一套；原始文件没有改写。那些机制需要独立、可恢复的动作状态与真实设备验收，不能把删除源码目录当作卸载实现。

| 本地明文设置 | 同一账户可读取自己的处境、誓言与配对资料 | 后续使用系统凭据库保护 token，另设计导出和加密备份 |
| 事件记录未统一 | 手机最近200条，桌面有界本地判断/通信日志；两端不共享历史 | 如需要，再定义跨端事件账本与保留策略 |
| 有限联动 | 30秒去重不是统一状态，断网可能双端重复提醒 | 如确有需求，再实现幂等事件 outbox、设备撤销和冲突规则 |
| Android 目标 API 35 | 当前侧载可用性与商店发布是不同验收范围 | 商店发布前调整目标 API、签名和敏感权限用途说明 |
| 模型未实连 | 自动测试使用模拟服务，不能证明某服务兼容 | 由用户选择服务后做一轮最小数据的连接测试 |

## 实际效果怎么判断

本版能减少“承诺被忘掉”的机会，也能在明确红线活动持续时把提醒送到面前。但没有证据说明更尖锐的话一定带来更多行动；也不能按 INTP 标签预言个人效果。效果还取决于规则是否准确、当下任务是否可执行，以及提醒是否已经变成背景噪音。

建议第一轮个人试用只观察一项主线，先用默认强度。每天自行记下：收到几次有效提醒、几次误提醒、收到提醒后是否真正返回，以及是否开始为了躲通知而改设置。这个观察不要求程序验收成果。若提醒增加但行动不增加，应先检查规则与出现时机，而不是自动加大措辞或锁屏次数。

具体措辞可以保留冷峻感，但程序只能引用你确认过的现实与后果。它没有证据替你生成关于人格、能力或未来结局的新判断；这也是第一版固定模板、AI 不生成惩罚话术的实现边界。
