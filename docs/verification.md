## 构建环境与产物

- 本机 Windows 11 64 位，Python 3.14.7，PyInstaller 6.22.3，cryptography 50.0.2。
- Android 使用本机已有 Unity AndroidPlayer 中的 OpenJDK、Android SDK Platform 35、Build Tools 34.0.0。构建脚本也接受外部 SDK/JDK 路径，不要求安装 Unity。
- Android 使用 Java 8 源代码级别、minSdk 28、compileSdk/targetSdk 35；Gradle 工程随源码提供，实际构建走 SDK 工具链，未额外验证 Gradle 构建。
- 产物位于 `../dist/`。精确大小与 SHA-256 以 [SHA256SUMS.txt](../dist/SHA256SUMS.txt) 为准。EXE 未商业签名；APK 使用本地开发签名。
- APK 的本机开发签名保存在 `android/build/ironwill-development.jks`，不放进源码包。此密钥只用于本产品测试；后续需要覆盖更新时应保留。重新生成不同密钥的 APK 通常不能直接覆盖现有安装。

最终 EXE 自检记录位于 `../dist/windows-self-check.json`，其中 `monitoring/network/lock` 均为 false，`ok` 和 `tls_dependencies` 均为 true。

## 本次修复并验证的问题

1. 桌面规则数值经核心规范化为浮点后，界面原来的整数解析无法保存默认参数；已统一有限数校验，默认开场有测试覆盖。
2. Android 原先把 relay 的202排队成功误报成失败；接受2xx，增加独立协议断言。
3. 手机选择未携带桌面周期身份可能作用于新周期；relay和UI均校验session_id，旧周期返回409或在消费时拒绝。
4. 手机“值得”被桌面强制理由字段静默丢弃；改为直接选择，符合三选语义。
5. 提醒去重拒绝可能永久吞掉桌面第三档；保留待提醒并重试，暂停、恢复、新周期会取消过期提醒。
6. Android 旧提醒、旧Activity与Service回调可能作用于新生命周期；新增当前周期、当前实例与生命周期检查。此部分编译和静态复核完成，旋转与重建的设备行为仍待验收。
7. AI 网络跳转可能把含标题的请求发送给另一个地址；禁止重定向，并用实际回环服务器测试不发生转发。

## 手动验收建议顺序

先填写一个普通测试目标和一条明确红线；先验证可暂停和退出，再用短阈值验证一次通知/提醒。确认周期结束后不再提醒、重开保持暂停，最后测试两端联动。真实锁屏仅在你方便重新登录时通过界面单独测试，不应成为首次打开的自动动作。
